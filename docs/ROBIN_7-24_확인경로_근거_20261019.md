- **근거:** E4 `구매 모듈 구성!A2:J16`, `구매 (2)!L7,Q7,Q9`. P1 실제 2장 5번 현황·Follow up.
- **남은 부분:** 실제 공급처 ERP 일정, 취소·반품·초과납의 계산 기준, 공식 입고 진척 분모는 미확정이다. 수량 합계는 동일 단위 검수 후 사용한다.

## 15. 플랫폼 사급품

- **확인 경로:** 플랫폼 수주 업무 상세 → 「15. 사급품」.
- **반영:** 고객사 사급·협력/제작업체 사급·일반 구매, 제공자/수령자, 예정/입고/투입 수량, 입고일, 원가 포함/제외/확인 필요, 소유권·유상/무상 근거를 기록한다.
- **시험:** 예정 10/입고 5/투입 2로 저장. 투입 6으로 변경 시 오류 확인. 원가 처리가 기본적으로 「확인 필요」인지 확인.
- **근거:** P1 실제 2장 4번의 현황·검토 방향·Follow up.
- **남은 부분:** 사급 원가의 자동 BOM 반영 및 ERP 재고/소유권 처리는 미연동이다. 구매와 생산 준비의 표시를 실제 ERP 처리와 혼동하지 않는다.

## 16. 가용재고·장납기·미래재고

- **확인 경로:** 수주 업무 상세 → 「16. 가용·미래 재고」.
- **반영:** 사업부 공통 현재고 기준·기준시각/근거와 수주별 확정 투입·입고예정·Forecast를 기록한다. 같은 사업부의 다른 수주 수요도 반영한다. `현재고 − 확정 예정 투입 + 입고예정`을 기준일까지 계산한다. 현재고 반영 거래는 재차 차감하지 않고 Forecast의 대응 확정수요가 있으면 중복 차감하지 않는다. 기준수량 미만은 부족 표시·담당자 To-Do를 생성한다.
- **시험:** 현재고 100, 다른 수주 수요 30, 입고예정 10 → 해당 기준일 예상 80. 같은 수요 근거번호를 중복 등록하면 오류. Forecast 시나리오는 별도 선택.
- **근거:** P2 실제 4장 9번 구현 검토·Follow up. P1 실제 5장 12번 예상 가용재고 식·Alert·Y+2/Y+3 검토.
- **남은 부분:** 실시간 ERP 재고 수신·예약/출고 원천·표준 달력·공식 Alert 기준은 미연동/미확정이다. 미반영 과거 거래를 기준 재고에 어떻게 정산할지는 ERP 규격과 함께 확정해야 한다.

## 17. 로봇 생산·협력사 배포·Serial·QR

## 18. 플랫폼 생산 공정 일정

- **확인 경로:** 플랫폼 프로젝트 → 생산 → 단계별 업무 상세 → 「18. 생산 공정 일정」.

## 22. 수주 이후 변경이력

- **시험:** 변경 후 값을 다시 수정하고 상세에서 이전 값을 확인한다. 완료/마감 상태에서도 과거 이력이 사라지지 않아야 한다.

- **남은 부분:** 기존 단계/납기/메모의 모든 예전 이력을 새 저장소로 이관한 것은 아니다. 실제 품의 승인, 재결재 기준, 변경 BOM 자동 표시·ERP 반영은 미연동/미확정이다.

## 23. 마감·수금·ERP 반영 상태

- **확인 경로:** 프로젝트 → 마감 → 단계별 업무 상세 → 「23. 업무종료·수금·ERP」.
- **반영:** 업무종료·출하·인수·Setup·ERP 매출·회계 상태를 분리한다. 계약금/중도금/잔금의 약정번호·계약액·실제 입금·은행 근거·입금일·세금계산서 참조를 기록한다. 같은 약정의 분할 입금은 계약액을 중복 합산하지 않으며 동일 은행 근거 중복을 막는다. 입금 기준 미수/수금률을 계산한다. ERP 요청은 「미전송」만 기록한다.
- **시험:** 같은 약정 1,000원에 200원+300원 별도 입금 → 계약액 1,000/입금 500/미수 500/수금률 50%. 세금계산서 참조만 바꿔도 입금액은 변하지 않아야 한다.
- **근거:** P1 실제 4장 11번·5장 13번. P4 실제 18·19장 세금계산서/계중잔·수금, 20장 원천 구분. E7 `마감_플폼영업!D17:P20`.
- **남은 부분:** 세금계산서 자동 후보 매칭은 미구현이며 원문상 후순위다. 실제 ERP 요청 송신·성공/실패·재처리·매출/회계 조회는 미연동이다. 수동 실제 마감 원가 참조는 공식 ERP 확정값이 아니다.

## 24. Home·To-Do·알림

- **확인 경로:** 각 업무에서 본인 담당 업무 등록 → Home To-Do 행 클릭 또는 상단 알림 목록.
- **반영:** 신규 불량·생산상태·Setup·변경·출하 준비·일정·사급 준비와 부족 재고를 담당자 To-Do에 연결한다. 신규 알림에서 같은 수주·같은 원본 상세로 이동한다. 기존 로봇/플랫폼 검토 To-Do도 원본 요청서를 열도록 연결한다. 본인 업무만 조회하고, To-Do 체크는 원본 결재/품질/ERP 상태를 승인하거나 변경하지 않는다.
- **시험:** 본인을 조치 담당자로 불량 등록 → Home에서 행 클릭 → 같은 접수의 원본 상세가 열리는지 확인. 타인 담당 건은 본인 목록에 보이면 안 된다. 불량 원본을 완료하면 해당 원본 업무 To-Do가 종료된다.
- **근거:** P1 실제 3장 7번 요청사항 마지막 항목. E6 `품질!K49,H11:H12`. P4 실제 5장 검토 상태 변경 알림. P3 실제 2장 1~3번 담당자별 업무·긴급건.
- **남은 부분:** 서버 실시간 알림·이메일·스케줄러·조직 부하 전체 지표의 실데이터 전환·종료 업무 알림의 영속 보관은 미구현이다. 전체 업무를 Home에 모으는 배치는 개발 제안이다.

## 완료 여부를 판단하는 기준

이 문서의 7~24번은 기본 프론트 작업공간과 임시 업무 흐름을 일괄 추가한 내역이다. 각 「남은 부분」을 포함한 전체 운영 요구가 완료됐다고 표시하면 안 된다. 특히 10번 옵션 자동 보정, 13번 LMBS/납기 자동 집계, 17번 실제 QR/현장 접속, 19번 성적서 자동 생성, 22번 기존 전체 이력 통합은 별도 구현이 남아 있다. 화면에서 입력·계산을 확인한 결과와 고객사 운영 규칙 확정 결과를 구분해 후속 작업한다.
